# Game Room — 8 вересня 2026

## Що змінилося

Онлайн-партія `/game/:gameId` і тренування `/play/computer` використовують
один `src/features/game-room/GameRoom.tsx`. Світла палітра, синя дошка, компактні
гравці та годинники, широка панель ходів. На телефоні дошка й панель розташовані
вертикально, основні дії закріплені внизу. Дошка на Full HD має 760 px.

Видалено старі `features/play/components.tsx`, `model.tsx`, `options.ts`, два
окремі макети партії, демонстраційні персонажі та репліки комп’ютера. Старий
ручний механізм перетягування замінено штатним механізмом react-chessboard з
єдиними SVG-фігурами. Незавершені функції не мають декоративних кнопок.

## Межі модулів

| Модуль | Відповідальність |
|---|---|
| `GameRoom`, `PlayerBar`, `ChessClock`, `GamePanel` | Макет, відображення часу, історія та вкладки |
| `BoardSettings`, `preferences` | Тема, фігури, координати, звуки, анімація, підсвічування, підтвердження ходу, автоферзь, зосередження |
| `GameControls`, `GameResult`, `GameInfo`, `GameChat` | Дії, завершення, фактичні дані та чат |
| `ChessBoard` | Легальність введеного ходу, вибір Q/R/B/N, кліки/drag, попередній хід, клавіатура |
| `useComputerGame`, `useTrainingHints`, `engine/` | Локальна партія, скасування обчислень, окремі workers |
| `useOnlineGame`, `GamePage` | Автентифікований WebSocket, підтвердження ходу, відновлення та архів |
| `server/game-rules.js` | Спільні причини завершення, включно з патом, повторенням, матеріалом, 50 ходами та часом |
| `server/server.js`, `supabase-persistence.js` | Авторитетні онлайн-ходи/годинники, збереження, рейтинг, реванш, скарги |

Ходи, час і результати онлайн визначає сервер. UI не оголошує програш за
локальним таймером; до підтвердження сервера наступний хід заблокований.
`moveId` і `expectedPly` захищають від повторного або застарілого запиту.
Перегляд історії не зупиняє годинники. Повернення ходу, пауза, підказки та
оцінка є тільки проти комп’ютера. Online Game Room не імпортує рушій.

Stockfish запускається у worker за потреби; скасований розрахунок не змінює
позицію після повернення ходу, паузи або нової партії. Виправлено зависання
старту: очікуємо `uciok`, не перевстановлюємо фіксовані Threads/Hash цієї WASM
збірки. Резервний локальний рушій також працює у worker. Він не видає свої
оцінки за Stockfish. Рівні комп’ютера позначені як орієнтовні.

## Виправлені помилки

- Запуск через HTTP без `crypto.randomUUID`: сумісний UUID на `getRandomValues`.
- Неправильні десяті секунди на годиннику та повтор звуку архівної партії.
- Застарілий хід рушія після Undo/Restart/Pause.
- Застаріла внутрішня позиція дошки після автоматичної відповіді у задачі.
- Накладання мобільної шапки на дошку, зайве прокручування на desktop.
- Можливість дублювання онлайн-ходу та невідповідність номера півходу.
- Нативні browser-confirm діалоги замінено керованими доступними діалогами.
- Пошкоджені налаштування дошки більше не зривають відкриття сторінки.

## Перевірка

- TypeScript `tsc --noEmit -p tsconfig.app.json`.
- Production-збірка Vite.
- 31 frontend-тест, зокрема 16 нових для Game Room і скасування Stockfish.
- 22 серверні тести. Інтеграція запускає справжній WebSocket-сервер та ізольовану
  тестову Supabase API: пошук, кольори, інкремент, мат, запис результату,
  повтор ходу, refresh/reconnect, чат, спам-ліміт, нічия, приватний архів,
  перетворення на коня, реванш і серверний timeout. Реальні акаунти та БД не змінюються.
- Браузер: запуск комп’ютера, фактична відповідь Stockfish, двоетапна підказка,
  Undo, хід перетягуванням, вибір дій, підтвердження здачі, результат і повторна партія.
- Справжній екран програми відрендерено в ізольованих viewport-контейнерах
  375×812, 768×1024, 1366×768, 1920×1080 та 2560×1440. Горизонтального
  переповнення немає; desktop повністю вміщується за висотою. Це перевірка
  верстки в Chrome, не випробування на фізичному телефоні.

## Розгортання та поточна межа перевірки

Frontend публікується через GitHub main → Vercel. Сервер потребує цієї самої
версії в Render. На момент перевірки `/health` відповідає 200, але `/api/play`
з Origin чинного сайту відповідає 403 `Origin is not allowed.`. Через це живу
партію між двома акаунтами на production поки не підтверджено.

У Render → Environment у `ALLOWED_ORIGINS` має бути точний origin:
`https://chess-of-odesa-21ada98f-main.vercel.app` — без кінцевого слеша.
Якщо є інші потрібні адреси, зберегти їх через кому. Після зміни розгорнути
останній commit сервера. Список доступу не розширюється до `*`.

Для коректного rated/casual і довільного контролю часу потрібна міграція 11
`20260906000000_flexible_play_ratings.sql`, якщо її ще не застосовано.
Міграція 12 `20260907000000_game_room_reports.sql` додає приватне збереження
скарг. Без неї кнопка скарги прихована; гра не залежить від цієї таблиці.
Застосовувати лише ще не виконані міграції за `supabase/README.md`.
Доступу до налаштувань Render і SQL Editor у цьому робочому середовищі немає.

Чат зберігає останні 100 повідомлень у пам’яті сервера і відновлюється після
оновлення браузера, але не після перезапуску Render. Вимкнення суперника
приховує його чат лише на цьому пристрої; серверне блокування матчмейкінгу
не реалізоване. Скарги записуються для перевірки, адміністративного інтерфейсу
модерації та автоматичних санкцій у цьому етапі немає.
